Benchmark scores for network intrusion detectors hide problems that appear only on the way to deployment. We audit one ordinary detector, a decision tree on 54 NFStream flow features, from labels to live blocking on an emulated Open vSwitch gateway, and condense the audit into four checks that others can run. \emph{Labels:} 91--98.5\% of flows in the CIC-IoT2023 web, brute-force and MITM captures are background traffic; training on file-name labels yields a true macro-F1 of 0.396 and flags 71.8\% of benign flows, against 0.725 and 3.8\% with evidence-based labels. On IoT-23, scored against the dataset authors' own Zeek labels, file labels give 0.169 and flag 98.5\%. \emph{Splits:} on CIC-IoT2023 a random split hides that brute-force recall falls from 1.00 to 0.05 when the target changes from SSH to RTSP (three host pairs); on IoT-23 the temporal--random gap does not replicate and comes from classes missing from one half, which makes class presence and host-pair intervals part of the check. \emph{Live:} matching live to offline flows one by one exposed a forwarding pitfall, idle flow meters and an NFStream ordering defect that delayed verdicts by up to 82.5\,s. \emph{Response:} blocking on the first verdict blocked 60 benign host pairs; requiring 10 verdicts blocked none but missed the Mirai and web attackers. Code, data and the audit scripts are public.
